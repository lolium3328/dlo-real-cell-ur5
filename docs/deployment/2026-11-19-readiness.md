# 2026-11-19 双 UR5e 启动前准备

## 计划

1. 校验原始部署包，在 Windows 上用 `uv` 建立 Python 3.11 环境。
2. 运行软件预检和模拟场景，记录延迟和终止原因。
3. 独立确认两台 RealSense 的串号、帧率和亮度。
4. 获得两臂地址和现场操作条件后，再完成实机预检、双探针对点与场景可行性检查。启动电机运动属于下一阶段。

## 结果

- 原始部署包中 156 个文件全部通过 SHA-256 校验。收到的目录没有 Git 元数据，已建立本地仓库并保存原包快照（`40340ec`）。
- `uv` 创建了 Windows Python 3.11.15 环境，按 `requirements.txt` 安装依赖，Torch 使用 `2.11.0+cpu`。修正 Windows CPU 使用率检查和中文 JSON 文件的编码后，文件完整性、依赖导入、BLAS 单线程和磁盘检查均通过。
- 完整 dry-run 停在软件预检（E700）。30 次决策延迟 p50 为 102 ms，p95 为 125 ms，超过 80 ms 门槛。单独复测、限制 OpenCV 为单线程、限制进程到性能核心，以及两者并用，p95 均为 125 ms。
- 用 `perf_counter` 复核，单次决策端到端 p95 为 122.7 ms。其中规划 p50 为 73.2 ms，p95 为 77.0 ms。视觉跟踪在 371 次调用中的 p95 为 36.7 ms。各项耗时的百分位数独立统计。
- 临时将 Torch 改为 2、4、6 线程复测，最佳 p95 为 94 ms。对 4 和 6 线程分别限制到性能核心，p95 仍为 94 ms。禁用 MKLDNN 的单线程复测 p95 为 125 ms。这些设置仅用于诊断进程。
- `--dry-run --check-only --scenes test_reach_0087` 的模拟可行性通过。该模式跳过决策延迟测试，使用模拟机械臂和逆运动学。
- 两台 RealSense 均以 USB 3.2 连接。`front`（`001622072105`）和 `top`（`837212070312`）的帧率均为 30 Hz，亮度检查通过。
- 左臂夹持绳子的活动端，右臂携带障碍球。按提供顺序暂将 `192.168.1.103` 用作左臂、`192.168.1.203` 用作右臂，两台均可通过 RTDE 读取。读取时均为 `POWER_OFF`、安全模式 `NORMAL`，未触发急停或保护停止。两台均报告负载 0.09 kg，实际工具质量和重心待现场核对。
